**Goal:** Ship the first wave of the Muse-parity roadmap: a daemon-built activity record, a network floor for the agent, goals and memory v2, and a phone-first web app with passkeys and push.

## Global Constraints

- Commits: conventional prefix with scope + plain-English sentence about the behaviour (e.g. `feat(activity): …`); authored as the user (`Aiden Yoon <44089734+yansigit@users.noreply.github.com>`), **no trailers**.
- Each lane works only in its own worktree on its own branch, cut from `main` at `a7e3c9e` or later. Never push to `main`; the coordinator opens PRs and merges.
- Every task: failing test first; then `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, the task's tests, then `cargo test` for the crate before committing. `cargo deny check advisories bans` after any dependency change.
- Tests wait on events, never fixed sleeps; router tests that wait on the tick set `cfg.tick = Duration::from_millis(200)`; never assume reply order a slow machine can reorder.
- `fake-rpi.py` mirrors the plugin and the gate: a change to `gateway_kind`, `GATEWAY_COMMANDS` or the gate protocol updates the Python mirror in the same commit.
- Never put tokens, vault values or fact values into logs, `Debug`, audit rows, notices or errors; every activity line is scrubbed on read (`gate::Scrub`: vault, then facts).
- Root never runs anything the agent could have placed: root's binaries by full path; files root publishes for the agent go in a root-owned 0755 folder (`<state>-public`), never the agent's home.
- Schema: current `SCHEMA_VERSION` is 16 (`store.rs:7`). B adds v17, W adds v18; each bump extends `older_databases_migrate_in_order_and_keep_their_rows`. A4 and A2 add no schema version.
- Ports: attach 7790, iMessage webhook 7791, egress proxy 7792 (A2), web app 7793 (W). Under A2's bridge mode every listener binds the container's own address and is published to host loopback only; the owner fronts the web app and the iMessage webhook with `tailscale serve`.
- No new crates beyond: hyper's `client` feature (A2) and `tokio-tungstenite =0.21.0` as a direct dependency (W). Passkeys and Web Push are built on `ring`.
- DESIGN.md and README.md change in the same task as the behaviour they describe.
- Never test against the live `zephyr` container. A side container uses `ZEPHYR_CONTAINER=zephyr-test ZEPHYR_IMAGE=zephyr-dev:<sha>` with its own data dir.

## Review Focus

1. **A2: an IPv6 address carrying an IPv4 one** (`::ffff:127.0.0.1`, `::ffff:7f00:1`, `64:ff9b::a9fe:a9fe`, `::127.0.0.1`): the proxy refuses it. Test in the A2 proxy-policy task.
2. **A2: a name that resolves to one public and one private address** (DNS rebinding): the whole request is refused, never retried on the public one. Test in the A2 proxy task.
3. **B: a task report or an owner-sent file, read in the same conversation, then a clean-looking owner turn that edits MEMORY.md**: it waits for `/memory ok`, never auto-approves. Test in the B provenance task.
4. **W: a passkey assertion replayed for a different proposal, or for the same proposal after its payload changed**: refused, and the action does not run. Test in the W passkey task.
5. **A4: pruning a database where a one-shot job's only run is older than 90 days**: the job does not fire again, and a new task's report is not dropped as a duplicate. Test in the A4 prune task.
